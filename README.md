# Designer Pricing Assistant

An independent or student designer enters an item's attributes (material,
category, region) and gets a fair price suggestion, backed by real
comparable listings pulled from Etsy.

## How it works

1. **`src/etsy_collector.py`** pulls handmade-clothing listings from the
   Etsy Open API v3 (price, materials, tags, category, shop region,
   favorites, images) into `data/raw/listings.csv`.
2. **`src/features.py`** turns raw listings into model-ready features:
   category, primary material, material count, region, quantity, etc.
3. **`src/train_model.py`** trains an XGBoost regressor (with a Ridge
   baseline for comparison) to predict price, and writes a cleaned
   comparables table the app searches for similar real listings.
4. **`app.py`** is the Streamlit demo: pick attributes in the sidebar, get
   a price estimate + range, and see the real listings it's based on.

## ⚠️ A note on where to run the collector

This repo was scaffolded in a sandboxed dev environment whose outbound
network is limited to package registries (PyPI, npm, GitHub, etc.) — it
cannot reach `api.etsy.com`. So `src/etsy_collector.py` has **not** been run
for real yet. Everything else (features, training, the app) has been built
and tested end-to-end against a synthetic sample dataset
(`data/sample/listings_sample.csv`, generated by
`src/generate_sample_data.py`) that mirrors the exact schema real Etsy data
will have.

**To get real data:** run the collector on your own machine (anywhere with
normal internet access):

```bash
export ETSY_API_KEY="your_keystring_here"   # from etsy.com/developers/register
pip install -r requirements.txt
python src/etsy_collector.py --target 3000 --out data/raw/listings.csv
python src/train_model.py                    # auto-detects data/raw/listings.csv
streamlit run app.py
```

Nothing else needs to change — `train_model.py` prefers `data/raw/listings.csv`
over the sample set automatically, and the app reads whatever
`data/processed/comparables.csv` training produced.

## Quickstart with the synthetic sample data (works right now)

## A modeling note: favorites as a demand signal, not an input

The brief calls for favorites as an engineered feature. A brand-new,
unlisted item always has 0 favorites/views, so feeding that in as a live
*input* to the app wouldn't reflect anything real about the item being
priced. Instead, `train_model.py` uses `log1p(num_favorers)` as a **sample
weight**: listings the market has already validated with engagement count
more when the model learns price patterns, while the app only asks for
what a designer actually knows before listing (material, category,
region, quantity). See the docstring in `src/features.py` for details.

## Project structure

```
designer-pricing-assistant/
├── app.py                       # Streamlit demo
├── requirements.txt
├── src/
│   ├── etsy_collector.py        # real Etsy API v3 pull (run outside this sandbox)
│   ├── generate_sample_data.py  # synthetic stand-in data, same schema
│   ├── features.py              # shared feature engineering
│   └── train_model.py           # trains + evaluates + saves the model
├── data/
│   ├── raw/                     # etsy_collector.py output goes here
│   ├── sample/                  # synthetic sample dataset
│   └── processed/               # comparables.csv used by the app
└── models/
    ├── price_model.joblib       # fitted sklearn Pipeline (preprocessing + XGBoost)
    └── metrics.json             # held-out MAE / MAPE / R2
```

## Current sample-data results

Trained on 3,500 synthetic listings (`python src/train_model.py`):

| Model          | MAE    | MAPE   | R²    |
|----------------|--------|--------|-------|
| Ridge baseline | $12.39 | 15.0%  | 0.855 |
| XGBoost        | $11.36 | 13.9%  | 0.885 |

Numbers will shift once trained on real Etsy data — the synthetic
generator's noise level was chosen to be a reasonable stand-in, not a
promise of real-world accuracy.
